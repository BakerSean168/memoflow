# 密码找回与重置实施方案

## 文档地位

本文承接 [App Vue 前端 UI 深度重构与功能性修复执行方案](./2026-07-15-app-vue-ui-and-functional-deep-refactor.md) 中明确延期的密码找回能力。当前登录页继续隐藏“忘记密码”入口，直到本文的服务端、安全、邮件和端到端验收全部完成。

## 当前状态

状态：**待实施**。

当前仓库已有邮箱密码注册、登录、稳定错误码和字段级反馈，但没有可用于生产的邮件投递、一次性重置令牌、密码重置接口或完整审计闭环。不得通过占位链接、固定验证码或仅前端页面把该能力伪装为可用。

## 目标

- 用户可以提交邮箱并收到不泄露账号存在性的统一反馈。
- 已注册账号可以通过短时、一次性链接设置符合共享密码 Schema 的新密码。
- 重置成功后令牌立即失效，既有会话按安全策略撤销，并留下可审计事件。
- Web 与 Desktop 共享同一服务端契约；入口只在完整链路可用时开放。
- 邮件失败、过期、重复使用、限流和异常重试具有稳定错误码与可翻译反馈。

## 非目标

- 不实现短信找回、人工客服重置或安全问题。
- 不在日志、URL 查询分析、前端存储或数据库明文保存原始令牌。
- 不使用“邮箱是否存在”的差异响应帮助账号枚举。

## 安全与数据契约

1. `POST /authentication/password-recovery/request`
   - 输入复用共享邮箱 Schema。
   - 无论账号是否存在都返回相同成功语义。
   - 按 IP、邮箱摘要和时间窗限流。
2. `POST /authentication/password-recovery/reset`
   - 输入包含原始一次性令牌和新密码。
   - 新密码复用注册密码 Schema，不维护第二套复杂度规则。
   - 令牌只在接收时出现；持久化保存强哈希、过期时间、使用时间和账号关联。
3. 令牌默认短时有效、单次使用；签发新令牌时可使旧令牌失效。
4. 重置成功后撤销该账号既有 refresh sessions，并记录安全审计事件。
5. 邮件链接使用配置中的公开 Web origin，不从请求头拼接不可信 host。

## 实施阶段

### 阶段 1：领域与持久化

1. 增加恢复令牌实体、自然键/索引和清理策略。
2. 增加请求恢复、验证令牌和重置密码用例。
3. 接入密码哈希、会话撤销、审计事件与稳定错误码。
4. 为并发消费、过期、重复使用和账号枚举防护增加集成测试。

### 阶段 2：邮件基础设施

1. 建立邮件投递端口与生产适配器。
2. 增加本地邮件捕获运行时，供开发和 E2E 读取真实邮件链接。
3. 为投递失败、重试和可观测性建立明确契约。

### 阶段 3：Web 与 Desktop 入口

1. 增加请求恢复页和设置新密码页。
2. 提供字段级反馈、首错聚焦、语言即时切换和无障碍语义。
3. Desktop 通过外部安全链接或受控内部路由完成同一流程。
4. 只有后端能力探测和部署配置完整时才显示入口。

### 阶段 4：验收与发布

1. E2E 覆盖请求邮件、打开链接、重置、旧密码失效、新密码登录和令牌重放失败。
2. 覆盖未知邮箱同响应、限流、过期和多语言错误。
3. 完成 Web、Desktop 和 prod-like 验收后再开放入口。

## 完成定义

- [ ] 恢复令牌以哈希形式持久化并具备过期、单次消费和并发保护。
- [ ] 邮件投递具备生产适配器与本地可测试运行时。
- [ ] 请求与重置接口复用共享邮箱/密码 Schema，并防止账号枚举。
- [ ] 重置成功后既有会话按策略撤销且有审计记录。
- [ ] Web 与 Desktop 完整 E2E 通过。
- [ ] 部署配置、监控和回滚说明完成后入口才可见。
