# PVC-TASK-3301C

1. Extract the existing Goal inputs/preview into a public Goal composer that reads authoritative preview context and emits value/note intent. Preserve selectors, finite validation and keyboard semantics.
2. Add one Prompt decision session to the Task action coordinator, resolved from each host's current Plan binding. Keep the Task complete command as the sole completion write and retain draft/session after failures.
3. Compose the Goal surface in one Task dialog used by Home/Inspect, Detail and Quick Surface. Complete-only remains available through Goal read failure.
4. Add Goal update-record orchestration and correction access for Manual/TaskUserMeasurement in recent progress; preserve provenance and Task state. TaskAutomatic stays read-only, with no correlated-record delete action.
5. Verify focused UI, Task/Goal completion/correction/revert tests, affected typechecks, changed-file lint, diff and governance. Do not push schemas, commit or push Git.

Contracts: use existing Task/Goal schemas and owner commands, Goal preview calculator and versioned mutation receipts; no new persistence or transport architecture. One pending session/action per Task surface, immutable source correlation, and at-least-once revert/reapply behavior remain the invariants.

## Result

Implemented PVC-TASK-3301C only. One Task-owned coordinator session resolves the current host's Plan binding. Fixed/LinkOnly complete directly; Prompt opens the shared Goal composer with the editable suggestion. Measurement submits only `completeOccurrence(id, { goalMeasurement: { value, note } })`; complete-only submits `completeOccurrence(id)`. Command failure retains session/draft, while success/cancel clears it. The busy guard covers commands and owner refresh and blocks conflicting session actions.

Goal owns the public composer, authoritative GOAL-1202 preview read/calculator, method vocabulary, signed/zero finite validation, notes and keyboard behavior. Task hosts own dialog/footer/close actions and reuse that surface in Home/Inspect, Detail and Quick Surface (Capsule/DailyTodoWidget). Existing Goal dialog/form/input/save selectors remain available. Goal context failure shows localized preview-unavailable text and leaves complete-only usable.

Goal Detail recent progress exposes Manual/TaskUserMeasurement correction through GoalRecordDialog. The Goal update adapter attaches expectedVersion, applies the owner mutation receipt, and refreshes the workspace through the existing saved event. TaskAutomatic is read-only. No Task status command or normal correlated-record delete is part of correction. The public Goal component has no Task imports or persistence decisions.

Uncomplete continues to use the existing Task command/outbox revert. A new real Goal handler/use-case characterization proves Prompt apply/retry, source-correlated revert/retry, restoration of tracking fallback and replacement apply/retry; one source has one active user measurement. No production backend, schema, provenance or route changes were needed. Correction preview does not present append-style arithmetic as a replacement preview; owner persistence recalculates the complete edited history.
