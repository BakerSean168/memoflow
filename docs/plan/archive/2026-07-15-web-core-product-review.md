# Web 登录后主要功能内部产品审查

## 摘要

本次以新注册测试用户的首次使用路径，对 Web 端 AI 工作区、目标、任务、笔记、提醒、通知和 Dashboard 退役状态进行了内部产品审查。

当前版本已经具备可理解的产品骨架：AI 是常驻工作区，目标、任务、笔记、提醒和通知通过顶部胶囊进入侧边业务面板，用户可以在不离开 AI 上下文的情况下管理结构化数据。Gemini 普通对话和目标 Agent 均能完成真实模型调用，目标、任务模板、Markdown 笔记和提醒模板也都可以创建。

但当前仍存在多处阻断核心闭环的问题：今日任务无法完成、通知列表因数据映射错误无法加载、知识库索引字段与数据库不一致、编辑器工作区初始化发生唯一约束冲突。产品已经可以用于内部展示和探索，但不适合把“任务执行、通知触达和知识库问答”描述为稳定可用能力。

本轮只恢复测试环境、配置测试所需 AI Provider 并生成审查文档，不修改业务代码。

## 环境与测试边界

### 目标环境

- 浏览器入口：`http://localhost:58080/`
- 实际端口转发目标：`ssh DO-bodysense`
- 远程项目目录：`/opt/memoflow`
- 远程编排文件：`docker-compose.local.yml`
- 远程环境文件：`.env.production.local`
- API：`53080`
- Web：`58080`
- AI Service：`58100`
- PowerSync：`58081`

`ali-memoflow` 不是本次 `58080` 对应的开发环境，不应使用该连接进行本轮验证或配置。

### 测试账号恢复

数据库版本更新后，原测试账号数据已经丢失。使用仓库约定的测试邮箱走正常注册流程后，账号成功创建并立即进入工作区；目标数据库中能够确认该邮箱存在一条账号记录。

这验证了本次账号失效主要是测试数据丢失，而不是登录协议、密码算法或前端登录逻辑损坏。

后续建议采用以下恢复顺序：

1. 先尝试使用固定测试账号登录。
2. 登录失败时按邮箱确认账号是否存在。
3. 账号不存在时优先走正常注册流程，顺便覆盖真实注册链路。
4. 只有注册链路本身不可用时，才使用适配当前数据库版本的幂等 seed 或 upsert 脚本直接插入。
5. 数据脚本必须以邮箱为条件，存在时不重复创建，不把这类测试恢复逻辑写进正式登录业务。

### Gemini 配置

当前产品的正常 AI Key 链路是：

1. 用户在“设置 → AI → 快捷提供方配置”中填写 Gemini Key。
2. API 使用 `AI_PROVIDER_ENCRYPTION_KEY` 加密第三方 Key。
3. 加密结果保存到当前用户的 AI Provider 配置中。
4. AI 调用时由 API 解密并传递给 AI Service。

因此，Google Key 不应直接作为普通环境变量写入 AI Service；环境文件中需要补充的是独立的 Provider 加密密钥。本次已在正确的开发服务器上生成 32 字符随机 `AI_PROVIDER_ENCRYPTION_KEY`，重建 API 后服务恢复健康。

随后通过产品设置保存 Gemini Provider，界面确认：

- Gemini 已配置并设为默认 Provider。
- 默认模型为 `gemini-2.5-flash`。
- 自动发现 40 个可用模型。
- Key 输入框在保存后被清空。
- 普通 AI 对话能够正常返回中文结果。

Google Key 未写入本文档，也未写入受版本控制文件。

## 做得好的部分

### 1. AI 常驻工作区方向成立

- AI 对话不会因为打开目标、任务、笔记等业务面板而卸载。
- 首页把快捷对话、今日任务、提醒和目标进度放在同一上下文中，能够表达“思考与执行在一个工作区完成”的产品方向。
- AI 生成期间输入框会禁用，并提供“停止生成”；完成后输入恢复。
- 模型缺失时能够引导用户前往设置，Provider 同步完成后模型选择器自动恢复。

### 2. 业务面板保持上下文

- 顶部模块预览可以先给出数量和简要状态，再决定是否进入完整面板。
- 多个业务面板以标签形式保留，用户可以在目标、任务、笔记、提醒和通知之间切换。
- 首页会在数据同步后反映新目标、新任务和进度，说明跨模块概览方向正确。

### 3. 创建表单覆盖面较完整

- 目标表单包含描述、分类、重要性、时间线、提醒和关键结果。
- 任务模板包含时间类型、重复、提醒、关键结果链接、父任务、颜色和标签。
- 提醒模板包含触发时间、重要程度、分组、活跃时段和高级通知设置。
- AI Agent 在真正写入目标、关键结果、任务和提醒前会进入审批状态，没有直接执行批量副作用。

## 主要问题

### P0：今日任务无法标记完成

#### 现象

新建任务模板后，今日概览成功出现对应任务实例。点击“标记完成”后，任务仍保持 `0/1`，页面只提示：

- 操作失败
- 提交信息不合法，请检查后重试

#### 产品影响

创建任务只是准备动作，完成任务才是日常使用的核心闭环。该问题会直接阻断用户最重要的执行反馈，也会使完成率、目标进度和统计数据失去可信度。

#### 优化要求

- 修复任务实例完成请求的字段或版本契约。
- 服务端返回可定位的稳定错误码，前端不要用通用校验文案掩盖具体原因。
- 增加“创建今日任务实例 → 完成 → 首页变为 1/1 → 统计更新”的端到端回归。

### P0：通知数量存在，但通知列表无法读取

#### 现象

- 创建提醒后，顶部通知徽标显示 `1`。
- 通知预览显示“暂无通知”。
- 完整通知中心同时显示“1 未读”和“暂无通知”。
- 等待数据同步后仍然不一致。

远程 API 日志显示通知查询在映射 Channel 时失败：一个 `INotificationId` 被当作 `INotificationChannelId` 解析，导致列表请求异常终止。

#### 产品影响

用户会看到有消息却无法读取，且“全部已读”与空列表同时出现。这比没有通知更损害信任，因为系统主动告诉用户有待处理信息，却不给出处理路径。

#### 优化要求

- 修复通知持久化映射中的 Channel ID 字段来源和类型前缀。
- 对历史错误记录提供清理或兼容策略，避免一条坏记录拖垮整个列表。
- 未读数量必须由可成功读取的通知集合产生。
- 增加“提醒触发 → 生成通知 → 列表展示 → 标记已读 → 徽标归零”回归。

### P0：笔记保存成功，但知识库索引不可用

#### 现象

Markdown 内容可以创建和保存，编辑器显示“已保存”。与此同时远程 API 日志显示：

- `ai_knowledge_index_entries` 缺少 `retrieval_vector` 字段。
- 知识索引写入的原始查询失败。

#### 产品影响

用户会认为笔记已经进入知识库，但“问知识库”、引用和检索能力可能无法使用。当前界面没有把“文件保存”和“知识索引完成”区分开，容易产生数据已经可被 AI 使用的错误预期。

#### 优化要求

- 对齐数据库 Schema、容器镜像和知识索引查询使用的字段。
- 显示笔记的索引状态：待索引、索引中、可检索、失败。
- 索引失败不能影响 Markdown 本身保存，但要提供可重试入口。
- 增加“创建笔记 → 索引完成 → 知识库提问返回引用”的端到端回归。

### P0：编辑器工作区初始化发生唯一约束冲突

#### 现象

新账号进入笔记模块时，远程 API 日志出现 `editorWorkspace.upsert()` 的 `project_path` 唯一约束失败；浏览器同时记录工作区确保失败。

#### 产品影响

当前用户仍能创建一条 Markdown，但工作区初始化状态不可靠。后续文件列表、资源选择、跨设备同步或新用户并发初始化可能出现不可预测问题。

#### 优化要求

- 确认工作区唯一键应以用户、项目路径还是两者组合建模。
- 新账号首次进入时使用真正幂等的初始化逻辑。
- 增加同一账号并发打开笔记模块的初始化回归。

### P1：提醒在已过时间创建后立即触发

#### 现象

在下午创建默认 `09:00` 的固定时间提醒后，调度队列先立即执行一次，再安排到次日 `09:00`。页面没有说明会补发当天已经错过的提醒。

#### 产品影响

用户可能在创建提醒时立刻收到一条意外通知，尤其是导入模板或批量创建时会形成噪声。

#### 优化要求

- 明确产品规则：已过时间是立即补发，还是从下一周期开始。
- 推荐默认从下一个有效触发时间开始；如选择立即补发，表单必须明确提示。
- 为当天已过、跨时区和夏令时场景增加调度测试。

### P1：导航按钮的可访问名称被数量徽标覆盖

#### 现象

无数据时顶部按钮名称是“目标、任务、笔记、提醒、通知”。创建数据后，目标、任务、提醒和通知按钮的无障碍名称都变成了“1”，只有没有数量的笔记仍保留名称。

#### 产品影响

键盘和读屏用户无法分辨多个名称相同的“1”按钮，自动化也无法稳定选择模块。数量徽标正在覆盖而不是补充模块名称。

#### 优化要求

- 按钮名称始终保留模块名，例如“任务，1 项”“通知，1 条未读”。
- 徽标作为补充描述，不应成为唯一可访问名称。
- 增加有数量和无数量两种状态的无障碍回归。

### P1：AI 目标规划的对话与承诺不一致

#### 现象

入口文案承诺先通过对话澄清背景、范围、成功标准和时间，但用户给出一句目标后，AI 立即返回一篇很长的完整计划，没有优先提出关键澄清问题。

#### 产品影响

用户会得到看似全面但未经确认的大段内容，阅读成本高，也削弱“共同澄清后生成结构化目标”的差异化价值。

#### 优化要求

- 第一轮只识别缺失信息并提出不超过三个高价值问题。
- 明确显示当前阶段：澄清中、可以生成、生成中、待审批、已执行或已取消。
- 对话正文优先简洁，详细行动计划放在结构化产物区域。
- Agent 的目标、说明、警告和动作描述应使用当前界面语言。

### P1：AI Agent 中英文混杂

#### 现象

中文界面中的结构化目标、目标说明、审批计划、风险提示和待执行动作大量使用英文；普通助手正文则是中文。

#### 产品影响

用户需要在同一工作流中频繁切换语言，且最终写入业务数据的标题可能与当前工作区语言不一致。

#### 优化要求

- 把当前语言作为 Agent 结构化输出的硬约束。
- 在审批前明确展示将写入系统的最终语言和文本。
- 对 Provider 返回的英文结构化字段进行语言校验，不符合时重新生成或提示用户。

### P1：任务概念对新用户不够清晰

#### 现象

顶部入口和主按钮称为“任务”“新建任务”，实际弹窗标题是“创建任务模板”。创建后先出现模板卡片，稍后才在今日概览中生成任务实例。

#### 产品影响

用户难以区分任务定义、重复模板和今天需要执行的具体任务，也无法预判创建后会发生什么。

#### 优化要求

- 明确区分“任务模板”和“今日任务实例”。
- 如果大多数用户意图是创建一次性待办，应提供更直接的一次性任务入口。
- 创建成功反馈说明“已创建模板，并生成今天的任务”。
- `20/100` 等分值需要名称或解释，不能只展示孤立数字。

### P2：Web 笔记创建尚未进入 GitHub 仓储闭环

#### 现象

- 空状态、工具栏和主区域同时出现多个“新建笔记”。
- 点击后立即创建带时间戳的 `Untitled` 文件，但不会自动进入编辑器。
- 用户还需要再次点击文件才能编辑。
- 正文一级标题不会同步为文件名，当前页面也没有明显的重命名入口。

以上是 2026-07-15 的实际产品表现。[ADR-034](../../architecture/adr/ADR-034-obsidian-vault-repository.md) 已在 2026-07-16 调整为本地 Vault + 可选 GitHub 知识仓库。Web 可以快捷创建，但必须创建 Git commit，不能继续优化当前数据库 `Untitled` 流程。

#### 优化要求

- 未连接仓库时引导创建/连接 GitHub private repository。
- 连接后提供唯一新建入口，由 Agent 生成完整写入提案并在用户确认后提交 Git。
- 首期不开放已有笔记编辑、重命名、移动和删除。
- Desktop 使用“在 Obsidian 打开”作为已有笔记编辑主操作。
- 文件列表项使用正确的可交互语义和可访问名称。

### P2：提醒列表缺少最重要的信息

#### 现象

提醒创建成功后的列表主要显示标题、“根目录独立控制”“未分组”和“自身控制”，没有直接展示触发时间、下一次触发时间和启用状态。

#### 优化要求

- 列表优先展示时间、重复规则、下一次触发和状态。
- 分组和控制来源作为次级信息。
- 对即将触发、已错过和暂停的提醒使用可理解状态。

### P2：反馈和本地化细节不一致

- 目标卡片使用 `0/0 KRs`、`90d left` 等英文信息。
- 任务创建成功提示出现两次。
- Agent 取消后主区域显示“已记录执行结果”，只有侧栏和提示明确显示已取消。
- `/dashboard` 不显示独立 Dashboard，但最终恢复到上次业务面板路由，而不是稳定跳转到 `/`。

这些问题不会单独阻断流程，但会持续削弱产品完成度和状态可信度。

## 建议实施顺序

### 第一批：恢复核心闭环

1. 修复任务实例完成请求。
2. 修复通知 Channel ID 映射和历史坏记录处理。
3. 对齐知识索引数据库字段。
4. 修复编辑器工作区幂等初始化。
5. 为以上四条增加远程环境可执行的端到端回归。

### 第二批：统一产品概念和状态

1. 区分任务模板与任务实例。
2. 明确已过时间提醒的调度规则。
3. 修复导航按钮的可访问名称。
4. 统一通知数量、列表和已读状态。
5. 统一 Dashboard 退役后的路由落点。

### 第三批：提升 AI 产品价值

1. 把目标 Agent 调整为先澄清、后产出。
2. 收敛首轮回答长度。
3. 强制结构化产物使用当前语言。
4. 提升审批、取消和执行结果状态的可读性。
5. 完成“AI 生成目标 → 审批 → 写入目标/KR/任务/提醒 → 首页更新”完整回归。

### 第四批：完成度与效率

1. 简化笔记创建和命名流程。
2. 重排提醒列表的信息优先级。
3. 清理重复成功提示和残留英文。
4. 补充关键按钮、编辑器和徽标的无障碍检查。
