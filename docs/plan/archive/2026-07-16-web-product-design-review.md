# Web 登录后工作区产品与设计复审

## 1. 审查结论

本轮以产品经理视角，在 `http://localhost:58080/` 的已登录测试账号中，对 AI 工作区、业务面板、目标、任务、笔记、提醒、通知、日程和设置进行了黑盒走查。审查只操作页面中的只读入口和未提交表单，没有修改业务数据或代码。

当前产品方向是成立的：AI 对话常驻，目标、任务、笔记、提醒、通知和日程作为可并行打开的业务面板，让用户在思考、生成和执行之间少跳转。相比传统的独立模块导航，这一结构有形成 Memory Flow 差异化体验的潜力。

当前最主要的问题不是功能数量不足，而是工作区的空间分配、核心对象层级和操作闭环尚未收敛：

1. 同时打开 AI 上下文和业务面板后，真正承载用户工作的业务区仍不够大。
2. 目标页没有把“目标 - KR - 进度记录”组织成一个可在列表中直接操作的连续单元。
3. 任务模块把模板、实例和今日执行混在同一个“任务”概念下。
4. 笔记页出现三组重复工具栏，空状态也没有形成明确的第一步。
5. 搜索按钮没有打开任何可见的搜索界面。
6. 多处设置页呈现了未完成、过度技术化或与当前产品能力不匹配的选项。

产品现阶段应优先完成“工作区布局收敛”和“目标、任务、笔记三个高频闭环”，再继续增加设置项或高级能力。

## 3. 做得好的部分

### 3.1 AI 与业务面板共存的产品结构有辨识度

- 用户可以保留当前对话，同时打开目标、任务、笔记等业务页面。
- 已打开模块会形成标签，返回不同业务上下文的成本较低。
- 在 `768px` 宽度下，业务面板会自动进入专注模式，说明响应式方向正确。
- 顶部模块入口可以提供数量和今日概览，适合高频扫视。

### 3.2 目标详情已经具备完整骨架

- 目标状态、重要程度、周期、整体进度、KR、进度记录和复盘均已存在。
- 没有 KR 时，“记录进度”不可用，业务规则基本合理。
- KR 表单已经覆盖起始值、目标值、当前值、计算方式和权重。

### 3.3 日程、提醒与通知已经形成数据关联

- 提醒可以显示下次触发时间和重复规则。
- 通知完整列表能区分同标题通知的相对时间。
- 日程能够展示任务实例，顶部“今日无安排”与当天日历数据一致。

## 5. 详细问题与建议

### P0-1：重新定义业务面板的拖拽范围

#### 复现与证据

在 `1440 x 1000` 视口同时打开 AI 上下文和目标业务面板时，实测布局约为：

- 会话列表：`260px`
- 中央对话内容：`346px`
- AI 上下文：固定 `384px`
- 目标业务面板：`449px`
- 业务面板拖拽热区：`8px`

把业务面板拖到最大后，中央对话可见内容只剩约 `36px`，但固定的 `384px` AI 上下文仍占据中间区域。因此业务面板左侧的整体工作区最小仍约为 `421px`，业务面板最大约为 `759px`。用户看到的是“对话已经几乎不可用，但业务面板仍不能继续扩大”。

左侧会话栏拖拽热区只有 `3px`，也明显偏窄。

#### 建议方案

1. 把“中央对话 + AI 上下文”视为一个可收缩工作区，而不是让上下文固定占用 `384px`。
2. 中央对话区域最小值设为约 `150px`；达到阈值后隐藏非必要内容，只保留会话标题、状态和展开按钮。
3. AI 上下文默认收起。业务面板开始向左扩展时，上下文应自动折叠，或改为覆盖式抽屉。
4. 业务面板最大宽度使用 `视口宽度 - 会话侧栏 - 150px` 计算，允许目标、笔记和日程成为当前主工作区。
5. 拖拽条视觉宽度可以保持 `1px`，但交互热区建议为 `12-16px`。
6. 拖拽条增加悬停反馈、双击恢复、键盘方向键调整和 `separator` 语义。
7. 用户调整后的宽度按模块或工作区持久化，不要在每次切换标签时跳回默认值。

#### 验收标准

- `1440px` 宽度下，业务面板可扩展到约 `1000px`，中央对话仍保留至少 `150px`。
- 展开业务面板时，AI 上下文不会成为不可收缩的固定阻挡。
- 拖拽热区在视觉上克制，但鼠标容易命中。
- `768px` 及以下继续使用业务面板专注模式，不出现多列硬挤压。

### P0-2：修复笔记页三组重复工具栏并落实 GitHub 知识仓库边界

#### 复现与证据

笔记主页同时出现三组完全相同的“文件、搜索、书签、重试、新建笔记”按钮。DOM 和页面截图均能稳定复现。

空状态左侧提示“暂无文件，导入资源或创建笔记开始使用”，主区域却显示“选择文件，从左侧选择一个文件开始编辑或查看”。这形成空状态死路，也没有表达 [ADR-034](../../architecture/adr/ADR-034-obsidian-vault-repository.md) 已采纳的“本地 Vault + 可选 GitHub private repository”边界。

#### 建议方案

- 工具栏只保留一组，并明确当前模式是“笔记”还是“规范”。
- 未连接 GitHub 知识仓库时，Web 提供“创建/连接 private 知识仓库”，不写数据库临时笔记。
- 连接后保留唯一“新建笔记”入口；Agent 生成完整写入提案，用户确认后创建 Git commit。
- Web 首期不开放已有笔记全文编辑、移动、重命名和删除。
- 有内容时显示仓库、最新 commit 和索引状态；webhook 延迟或授权失效时给出明确反馈。
- Desktop 对应页面以“选择 Vault”和“在 Obsidian 打开”为主操作，不再把自建编辑器作为长期主流程。

#### 验收标准

- 任意桌面和窄窗口尺寸下，工具栏只渲染一次。
- 未连接时能创建/连接 GitHub private repository，且不会误写数据库 Repository。
- 连接后 Web 新建产生 Git commit，重复请求不会创建重复文件。
- 已有笔记编辑和高风险文件操作仍不可用。
- 有投影时可预览、搜索，并看到最新 commit 与索引状态。

### P1-1：目标卡片改为整行目标工作单元

#### 当前问题

目标列表使用容器查询，在业务面板足够宽时会切为两列或三列卡片。卡片只展示目标摘要、`0/0` KR 和剩余天数，用户必须进入详情才能看到 KR 或记录进度。

目标标题使用可点击样式，但本身没有按钮、链接或键盘焦点语义。

#### 建议结构

每个目标占一整行，目标卡片内部包含一个横向滚动的 KR 区域：

```text
┌ 进行中  目标标题                         [添加记录] [更多] ┐
│ 描述 · 周期 · 总进度 · 剩余天数                         │
│                                                        │
│ [KR 1  45%] [KR 2  80%] [KR 3  20%] [ + 添加 KR ] →   │
└────────────────────────────────────────────────────────┘
```

- 目标卡片始终整行，不随宽度变成多列瀑布。
- KR 作为嵌套的小卡片横向排列，超出后水平滚动。
- 滚动区提供边缘渐隐或左右切换按钮，让用户知道还有内容。
- “添加记录”放在卡片顶部主操作区，不必先进入详情。
- 添加记录的快捷表单只要求：选择 KR、输入本次值或增量、备注、记录时间。
- 没有 KR 时，“添加记录”可替换为“添加第一个 KR”，避免禁用按钮成为死端。
- 点击卡片正文进入详情；主操作和更多菜单不触发详情跳转。

#### 验收标准

- 用户在目标主页两步内完成一次 KR 进度更新。
- 目标列表在 `600-1200px` 业务面板宽度下始终一行一个目标。
- 5 个以上 KR 不拉高整页，通过横向滚动浏览。
- 卡片整体和标题均可通过键盘进入，操作按钮具有独立语义。

### P1-2：搜索入口当前没有形成可见功能

点击左侧“搜索”后，页面回到快速对话首页；连续复核后仍没有搜索输入框、结果列表、命令面板或状态提示。按钮保持激活态，但用户无法判断搜索是否开启。

建议把搜索定义为明确的全局能力：

- 点击后打开命令面板式搜索。
- 默认同时搜索会话、目标、任务、笔记和提醒。
- 结果按对象类型分组，并支持键盘上下选择。
- 如果当前版本只支持搜索会话，应直接命名为“搜索对话”。
- 功能未完成前不要保留一个看似可用但无反馈的入口。

### P1-3：区分“任务模板”“任务实例”和“今日待办”

顶部入口叫“任务”，进入页面后显示“1 个任务模板”；卡片同时展示重复规则、总次数和完成率。顶部预览又使用“今日任务 0/0”。用户需要自己推断模板会生成实例，以及应在哪里完成今天的实例。

任务详情只展示模板基本信息、关系和执行统计，没有实例列表、下次执行时间或直接完成入口；依赖状态还混入英文 `None`。

建议：

1. 任务主页默认进入“今日待办”，模板管理作为次级标签。
2. 一次性任务直接创建一个实例；只有开启重复时才引入模板概念。
3. 模板详情展示“下次实例”和最近实例列表，统计数字可以下钻。
4. 创建成功反馈明确说明“已创建模板，并生成今天的任务”或“下一实例将在何时生成”。
5. 全部状态、本地化和字段名称使用当前语言。

### P1-4：把 AI 上下文从工程监控改为用户决策信息

当前上下文面板默认展示 `node.completed`、节点耗时、英文状态、运行事件、依赖动作和内部警告。它更像开发调试器，而不是用户用于确认目标的业务摘要。

建议分成两层：

- 默认层：用户意图、结构化草稿、风险提示、待确认动作和最终结果。
- 开发层：节点、耗时、事件和原始状态，收进“运行详情”折叠区，只在高级或调试模式显示。

取消运行后，主区域出现两次“已记录执行结果”，同时上下文显示 `cancelled`。需要统一为明确状态，例如“已取消，未执行任何写入”，并提供“基于草稿继续”或“丢弃草稿”。

### P1-5：控制业务标签增长

本轮依次打开目标、任务、笔记、提醒、通知和日程后，六个标签全部保留在业务面板顶部。窄业务面板中标签开始横向拥挤，关闭按钮也占用大量空间。

建议：

- 每个模块只保留一个单例标签，进入详情时复用同一标签。
- 显示最近 3-4 个标签，其余进入溢出菜单。
- 支持固定标签和“关闭其他标签”。
- 标签关闭按钮只在悬停或激活时显示，但必须保留键盘可访问性。
- 专注模式下将标签栏替换为模块切换菜单，减少横向占用。

### P1-6：避免加载期间闪现假空状态和假错误

在 `768 x 900` 直接进入目标页时，页面先显示：

- “所有目标 0”
- 目标卡片骨架
- “当前没有可用模型”

约 2.5 秒后才恢复为“所有目标 1”和 `Gemini 2.5 Flash`。这不是普通骨架问题，而是把未完成加载解释成了真实空数据和配置错误。

建议为数据、AI Provider 和业务面板分别建立 `loading / empty / error / ready` 状态；只有请求成功且结果确实为空时才显示“0 项”或“无可用模型”。

### P1-7：设置页需要删减未完成和不匹配能力

#### 通知与提醒

页面只有一个“自定义应用通知 / 系统原生通知”开关，没有通知类型、声音、免打扰时段、提醒默认值或渠道设置。页面名称与实际能力不匹配。

#### 账户与隐私

存在“在线状态、通过邮箱搜索、通过手机号搜索、个人资料可见性”等社交能力设置，但当前产品没有可见的联系人或社交场景，也没有手机号资料入口。隐私政策链接还是 `#`。

#### 数据

“导出设置、导入设置、Export All Data、Import All Data、本地备份、云同步、版本历史”集中在同一页，但没有解释格式、范围、目的地、覆盖规则和最近同步状态；中英文也不一致。当前目录只显示 `...`，用户无法确认数据位置。

#### 高级

“快捷键设置”只有搜索和“全部重置”，没有快捷键列表。“实验性功能”只有总开关，没有任何实验项。

#### AI

快捷 Provider、已配置 Provider 和高级手动 Provider 同时铺在一个长页中，重复出现刷新模型、连接、载入表单和测试连接。普通用户与高级用户路径没有分层。

建议遵循“没有真实能力就不展示设置”的原则，并把高级 Provider、实验功能、数据迁移收进清晰的二级页面或折叠区域。

### P2-1：通知预览应补时间和来源

通知弹层中两条通知标题和正文完全相同，看起来像重复数据；完整通知页显示它们分别是“大约 10 小时前”和“1 天前”。弹层也应显示时间、未读状态和来源，避免用户误判。

### P2-2：日程中的同名实例需要可区分

周视图在同一天显示三个同名、被截断的全天任务块。用户看不到实例状态、来源模板、完成状态或为何出现三次。

建议至少显示状态图标和序号；点击后展示来源模板、实例日期、执行状态和相关目标。相同模板的连续实例可以使用一致颜色，但不能只依赖颜色区分。

### P2-3：补齐交互语义和键盘操作

- 目标和任务标题可点击，但没有链接或按钮语义，也不能自然获得键盘焦点。
- 多个图标按钮在 DOM 中没有可访问名称。
- 业务面板拖拽条没有 `separator` 角色和键盘调整能力。
- 左侧拖拽热区只有 `3px`。
- 深色模式下大量次级文本、边框和禁用态对比度过低。

建议把关键流程纳入键盘走查和基础 WCAG 对比度检查，而不是只补 `aria-label`。

### P2-4：建立 Memory Flow 的视觉签名

当前页面主要由深黑、灰色、少量紫蓝高亮和大量卡片组成，整体更像通用管理后台。目标、KR、任务、提醒和笔记之间的关系虽然存在于数据中，却没有形成可见的“流”。

建议把视觉辨识度用在一个位置：用克制的“关系轨道”表达目标到 KR、任务、提醒和复盘的连续性。它可以出现在目标整行卡片和详情页中，其他区域继续保持安静、工具化。不要通过增加更多渐变、装饰卡片或大色块解决品牌感问题。

## 6. 推荐的响应式规则

### `>= 1280px`

- 会话侧栏：`220-320px`，可收起。
- AI 对话：最小 `150px`。
- AI 上下文：默认收起；展开时 `320-420px`，业务面板拖大时自动折叠。
- 业务面板：默认约 `44-50vw`，可扩展到扣除会话栏和 `150px` 对话区后的剩余宽度。

### `768-1279px`

- 打开业务模块后默认进入业务专注模式。
- AI 输入框缩为可展开的底部工具条，不持续占用约百余像素高度。
- 模块标签变成下拉切换器或紧凑滚动标签。

### `< 768px`

- 每次只显示一个主层：对话、业务页或上下文。
- 上下文使用全屏抽屉，不覆盖输入框。
- 目标 KR 横向滚动，主操作固定在标题区。

## 7. 建议实施顺序

### 第一批：修复明显不可交付问题

1. 修复笔记工具栏三重渲染。
2. 修复搜索入口无可见结果。
3. 修复加载期假空状态和假模型错误。
4. 完成业务面板、上下文和对话区的宽度规则。

### 第二批：打通高频工作闭环

1. 重构目标整行卡片、KR 横向区和快捷添加记录。
2. 区分任务实例、今日待办和任务模板。
3. 按 ADR-034 重做本地 Vault、GitHub 连接、Web 快捷创建和 Desktop 外部打开路径。
4. 收敛 AI 上下文的默认信息层级。

### 第三批：收敛系统级体验

1. 控制业务标签数量和专注模式切换。
2. 完善通知预览和日程实例信息。
3. 清理无真实能力支撑的设置项。
4. 统一中文、本地化、可访问名称和键盘交互。
5. 建立目标到执行的关系轨道作为 Memory Flow 视觉签名。

## 8. 回归验收清单

- [ ] 笔记工具栏在任意尺寸只出现一组。
- [ ] Web 未连接仓库时提供创建/连接 private repository，不写数据库临时笔记。
- [ ] Web 新建笔记产生幂等 Git commit，已有笔记编辑仍关闭。
- [ ] 已同步笔记可预览并显示最新 commit、GitHub 授权和索引状态。
- [ ] 搜索入口打开可见、可输入、可关闭的全局搜索界面。
- [ ] 加载中不显示“0 项”“暂无数据”或“没有可用模型”。
- [ ] `1440px` 下业务面板可扩展到约 `1000px`，对话区最小约 `150px`。
- [ ] 拖大业务面板时，AI 上下文自动折叠或覆盖显示。
- [ ] 目标主页始终一行一个目标。
- [ ] 目标卡内 KR 支持水平滚动，并可直接添加记录。
- [ ] 用户能明确区分今日任务实例和任务模板。
- [ ] 任务详情可下钻查看实例并操作最近或下一实例。
- [ ] AI 上下文默认不展示节点名、耗时和原始事件。
- [ ] 业务标签超过四个后进入可理解的溢出机制。
- [ ] 通知预览显示时间和未读状态。
- [ ] 日程同名实例可以通过状态、日期或序号区分。
- [ ] 隐私政策链接可用，未实现的社交隐私选项不再显示。
- [ ] 数据导入导出、备份和同步分别说明范围、格式、目的地和覆盖规则。
- [ ] 快捷键设置存在真实快捷键列表；没有实验项时不显示实验总开关。
- [ ] 可点击标题、图标按钮和拖拽条均支持键盘与读屏。
