# ADR-015: 优先考虑开发阶段的简洁性与优雅 (Simplicity over Compatibility in Dev Phase)

## 状态 (Status)

已接受 (Accepted) - 2026-01-16

## 配置信息 (Metadata)

- **决策人**: Baker
- **项目阶段**: 早期开发/原型阶段

## 背景 (Context)

项目当前处于快速迭代的开发阶段。在进行重构（如任务优先级机制重构）和代码优化时，如果强制要求保留向后兼容性，会产生以下问题：

1. **代码污染**: 为了兼容旧字段（如 `priority` 枚举）和新字段（如 `importance`），必须在 DTO 和 Entity 中编写大量的桥接代码。
2. **认知负担**: 开发者需要理清“过渡期”逻辑和“目标态”逻辑。
3. **迁移复杂性**: 强制推行复杂的生产级迁移策略（如 Expand and Contract）会拖慢开发进度。

## 决策 (Decision)

1. **不考虑兼容性**: 严禁在代码中保留为了兼容旧版本而存在的逻辑。
2. **优雅与简洁优先**: 所有重构必须以达成“最干净的代码结构”为唯一目标。如果一个字段不再需要，立即删除。
3. **破坏性变更许可**: 允许直接修改 `schema.prisma` 并重置数据库。
4. **一次到位**: 重构应该是对目标状态的直接实现，而不是渐进式的兼容性演进。

## 后果 (Consequences)

- **正面**:
  - 代码库保持高度可维护性，无腐态代码。
  - 逻辑清晰，易于 AI 代理理解和实现。
- **负面**:
  - 开发环境的持久化数据可能在重构后失效。
  - 需要频繁使用 `npx prisma migrate reset` 处理本地数据库。

---

_注：本 ADR 仅在开发阶段有效。进入 Beta/生产部署阶段后，需重新评估迁移策略。_
