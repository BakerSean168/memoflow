# Desktop Profile 产品与交互规格

**状态：独立容器、账号路由、访客复制导入、恢复和可选清理已实现；验证范围以实施计划为准。** 架构取舍见 [ADR-119](../../architecture/adr/ADR-119-independent-desktop-profiles-and-guest-copy-import.md)，实现安全条件见[导入协议](../../architecture/desktop-profile-import-protocol.md)。

## 1. 目标与范围

用户能够为工作、个人或临时项目创建独立本地资料空间，也能够添加多个云端账户并点击切换。登录成功后立即拥有正确的目标 Profile；数据导入是后续可选操作。

V1 支持多个 guest、多个云端 Profile、重命名、PIN、离线打开、按 ID 切换、向空云端账户复制一个 guest，以及验证后的可选源清理。V1 不新增自动跨云端账户合并、批量导入多个 guest、多活动窗口 Profile、服务端匿名访客或浏览器 Multi Session。Web 认证继续沿用既有逻辑。

## 2. Profile 菜单与管理页

Shell 左下角账户菜单展示当前 Profile 和按最近使用排序的其他 Profile，提供“创建本地 Profile”“添加云端账号”“管理 Profile”；活动云端 Profile 另有“导入本地 Profile”入口。正常切换不展示迁移选择。

每行显示名称、guest/云端身份、当前选中标记和可用的连接状态。相同名称允许存在，通过账号提示区分；名称不是身份。受 PIN 保护的行显示锁图标。云端“在线”不能写成“同步完成”，后者必须来自同步状态。

管理页复用现有本地访问列表，提供创建、重命名、PIN 解锁和本机移除。设置/移除 PIN 沿用打开后的账户与隐私页；导入从云端 Profile 菜单进入 ProductDialogShell，通用导入/导出沿用数据管理入口。Profile 名称是本机容器标签，修改它不自动修改 Account 昵称。云端账号注销不放在本机 Profile 删除按钮内。

| 动作               | 用户结果                                            | 失败时                                                         |
| ------------------ | --------------------------------------------------- | -------------------------------------------------------------- |
| 创建本地 Profile   | 总是创建新的 guest 并打开；默认生成不冲突的可读名称 | 当前 Profile 保持可恢复，显示失败原因；重试不能误建多个        |
| 点击未保护 Profile | 打开该 ID；保留旧 Profile 的资料                    | 停留在稳定旧运行时或明确本地访问页，不显示半切换数据           |
| 点击 PIN Profile   | 原位输入 PIN，成功后只打开选中 ID                   | PIN 错误保留选择、支持重试；清空离开后的输入，不读取其业务摘要 |
| 添加已有云端身份   | 恢复本机已有 Profile，必要时本地解锁                | 不新建副本，不再主动询问导入                                   |
| 云端 session 失效  | 标记“需要重新认证”，仍可打开本地资料                | 重新认证不锁定/删除本地 Profile                                |
| 本机移除           | 用户确认后清理该本地容器                            | 单独说明未同步资料风险；失败提供清理恢复状态，不宣称成功       |

列表刷新不得为每一行同步请求 get-session；连接状态可显示最近已知值及“尚未检查”，切换或用户重试时再验证。

## 3. 添加云端账号

1. 用户选择“添加云端账号”，进入现有设备授权弹窗；浏览器继续提供 GitHub/邮箱认证。
2. 授权返回后验证云端身份，在本机 registry 查找；已存在则使用该 Profile，否则建立独立云端 Profile。
3. 安全保存该 Profile 的 session，完成本地准备/必要 PIN 解锁和切换，显示“账号已添加”。登录期间不修改源 guest 的 Account、业务身份或资料。
4. 若符合下一节条件，展示一次可选导入弹窗；否则进入目标 Profile。同步尚未完成时显示同步进度，但不把新 Profile 的暂时空列表当成云端为空的证据。

用户在认证过程中切换/锁定发起 Profile，尚未提交的认证 attempt 作废；迟到结果不得切换当前用户或覆盖另一 Profile 的 session。连接协调器自己执行的目标切换属于同一次提交，不能误取消已提交 attempt。

从某个云端 Profile 选择“重新认证”时必须返回同一个云端身份；若浏览器选错账户，提示“这不是正在重新认证的账号”，允许重试或由用户另行使用“添加云端账号”。禁止悄悄改绑。

## 4. 一次性主动询问

| 已知条件                                                | 行为                                                 |
| ------------------------------------------------------- | ---------------------------------------------------- |
| 本机已存在此云端身份 Profile                            | 直接打开/解锁，不主动询问                            |
| 新 Profile，云端有业务内容                              | 直接打开，不主动询问                                 |
| 新 Profile，云端状态未知或请求失败                      | 登录照常完成；云端 Profile 菜单可手动发起            |
| 新 Profile，云端为空，本机没有可导入业务内容            | 不询问                                               |
| 新 Profile，云端为空，至少一个 guest 已证实有可导入内容 | 提供一次弹窗                                         |
| 所有潜在源均锁定、没有授权读取摘要                      | 不绕过 PIN 自动扫描；从导入弹窗输入源 PIN 后手动发起 |

以本机新建的 Profile 生命周期为单位记录自动询问是否已消费。检查摘要前先持久化消费记录，再返回 UI 提示，保证重复事件、重启、重认证不会重弹；持久化后 UI 崩溃可能错过该次提示，用户仍有手动入口。云端离线、没有候选等本次跳过原因也记录，不在用户以后工作时突然弹出。

自动摘要最多检查前 20 个 guest，不扫描/hash 附件；手动选择仍可访问其他 guest。

“云端为空”是导入机会，不是注册时间。归档/可恢复内容仍是用户数据；系统 Account、自动默认偏好和生成的运行记录不直接算已有业务内容。具体计数由 owner 定义，见协议。

## 5. 导入弹窗

沿用 ProductDialogShell，单层选择和确认，不做多步向导。

```text
导入本地资料？
云端账号已添加。可以将一个本地 Profile 中支持的资料复制到此账号。

本地 Profile    [选择本地 Profile]
可导入内容      [由预检结果显示的分类和数量]
另需保留        [未支持的笔记、消息或本机配置说明，仅有时显示]

[ ] 导入并验证成功后，删除原本地 Profile

[暂不导入]                              [确认导入]
```

- 自动提示唯一可用源时预选；手动打开只有一个 guest 时预选，多个 guest 时必须明确选择。
- 可列出锁定候选的名称和锁标记，但记录数量和具体内容只能解锁后获取。解锁后回到同一弹窗，保留目标云端身份。
- 数量来自同一个待导入快照和有效导入计划，不用表行数或示例常量。TaskPlan/Occurrence、Goal/KeyResult、AI 会话外壳用可理解的分类，不相加冒充“笔记数”。
- Account 默认资料和默认设置本身不让空 guest 触发主动提示。
- 有自定义资料/偏好但无业务内容的 guest，可手动复制或使用通用导出；不会触发主动提示。
- 明确提示“保留云端已修改的个人资料和设置”；未复制的源自定义值属于保留原因。
- Checkbox 默认关闭；存在不可迁移的用户资料、未核实的本地内容或源摘要不确定时禁用，并给出具体保留原因。
- 可再生成的缓存/索引/运行状态须由明确白名单识别；未知表/文件保留。V3 不包含 Vault、附件、AI 消息/凭据和 Routine protocol/session，不能承诺整个 Profile 已复制。
- 预检失败显示问题并允许重试/跳过；“暂不导入”、关闭或 Escape 在提交前均跳过本次，不退出云端登录。

## 6. 提交后与恢复体验

| 用户可见状态                 | 可用动作                    | 语义                                         |
| ---------------------------- | --------------------------- | -------------------------------------------- |
| 正在准备资料                 | 关闭面板；下次从记录恢复    | 主进程负责操作状态；关闭面板不销毁任务       |
| 正在导入云端                 | 关闭进度面板                | 写入结果不明确时不提供“已撤销”承诺           |
| 云端已导入，正在同步到此设备 | 稍后从记录重新核验          | 不重新 apply；本机未就绪不能删源             |
| 已完成，保留原 Profile       | 关闭弹窗、查看记录          | 默认完成态                                   |
| 已完成，原 Profile 已删除    | 关闭弹窗、查看记录          | 仅安全清理完成后显示                         |
| 已导入，原 Profile 需要保留  | 查看原因、从菜单切换源      | 例：源有新增任务、包含本地笔记或目标尚未核验 |
| 连接中断 / 需要认证          | 重试连接/认证               | 恢复原 operation，不能生成新批次重复导入     |
| 云端已有新内容               | 返回目标、通用导入/导出入口 | 原空账户计划失效；不自动切换为合并模式       |

恢复始终使用原 requestId。目标变化导致旧计划失效时，界面立即回到“等待预检”，删除勾选清空，再次预检后重新确认。

进度使用阶段和可证明数量，不显示虚构的百分比。超过等待期限显示“尚未完成核验，原 Profile 已保留”；后台可继续既有同步，但不得无限自动重试导入请求。

用户切到其他 Profile 或锁定应用时，暂停与当前 UI/密钥相关的后续步骤。服务器已提交的导入不受 UI 切换撤销；回来后从持久 operation 查询结果。自动清理不在源活动或源重新打开后继续。删除勾选在确认提交时固定；关闭弹窗不代表撤回已提交授权。核验失败会保留源。

## 7. 四个不同动作

- **锁定 Profile**：结束本地访问，需要 PIN 时重新解锁。
- **退出云端登录**：撤销当前 Profile 的云端 session，保留本地资料。
- **从本机移除 Profile**：删除此设备容器和其密钥，云端账户/业务资料继续存在；手动删除有自己的明确确认。
- **关闭云端账户**：沿用 Account closure 产品流程，不由切换/导入触发。

导入时一次勾选只授权清理该次捕获的源快照，不授权删除后续新增内容。自动清理被阻止后，用户可以手动管理源，但不能通过旧勾选静默绕过核验。

## 8. 无障碍与验收入口

使用既有 Dialog/Select/Checkbox/Input primitive；键盘可选择 Profile、解锁、确认与跳过；焦点进入标题后的首个操作，关闭后回到触发入口。后台进度通过非打断式状态文本播报，不靠颜色区别 guest/云端/错误。狭窄窗口正文可滚动，footer 操作持续可达。

需要中英文文案、明暗主题、长 Profile 名称、重名、键盘焦点、PIN 错误和同步离线状态验收。具体场景编号见[实施计划](../../plan/active/2026-10-09-desktop-independent-profiles.md)。
